# 使用案例

以下是可复制的任务示例与预期交付，用于说明怎样使用视觉设计工坊；不是已完成项目展示或各客户端实测记录。示例中的文件名可替换为自己的素材，实际交付取决于宿主可用工具。

在 Codex 中可在请求前加 `$visual-design`，在 Claude Code 中加 `/visual-design`；在 WorkBuddy 中先选择技能，再发送请求。下面使用通用的自然语言写法。

| 案例 | 适合解决的问题 |
| --- | --- |
| [1. 求职助手桌面工作台](#case-1) | 优化现有界面，保留全部业务功能 |
| [2. 运营数据后台](#case-2) | 提升信息层级、筛选效率和图表可读性 |
| [3. 品牌官网与动效](#case-3) | 从竞品研究建立有辨识度的视觉方向 |
| [4. iOS / Android 原生应用](#case-4) | 统一品牌表达，保留不同平台的交互习惯 |
| [5. Figma 设计与开发交接](#case-5) | 整理设计变量、组件状态与开发规格 |
| [6. 报告与演示文稿](#case-6) | 用清晰叙事呈现数据，交付可编辑文件 |
| [7. 海报与社交图片](#case-7) | 根据用途设计构图、字体和多尺寸版式 |
| [8. 项目内可复用组件](#case-8) | 把已选设计转成有状态、有接口的组件 |
| [9. Liquid Glass 材质修正](#case-9) | 让背景在边缘产生折射，保持控件清晰 |
| [10. 设计蓝图与反模板审查](#case-10) | 根据任务选择品牌参考，再检查默认模板模式 |
| [11. 界面层次与交互细节](#case-11) | 把强制规范落实到输入、数字、展开与反馈 |
| [12. 按用途组合交互动效](#case-12) | 根据组件职责选择效果，保留准确业务状态 |

<a id="case-1"></a>

## 1. 求职助手桌面工作台：改版不丢功能

**准备输入：** 现有项目、当前界面截图、必须保留的功能清单。若只需图片，提供截图和功能说明即可。

```text
使用视觉设计工坊优化这个求职助手桌面工作台。
使用者需要设置筛选条件、观察任务进度、复核岗位并查看沟通记录。
请先盘点原有功能和状态，再研究同类效率工具的信息布局与交互。
必须保留多城市与最低月薪、关键词、行业、运行状态、停止任务、
匹配依据、沟通记录和连接设置，不能为了简洁删掉功能。
本次已确定白底、天蓝色强调；这是本项目的配色选择。
先输出可比较的界面图，等我选定方向后再实现代码。
```

**预期交付：** 功能与状态盘点、有来源的竞品观察、2–3 个有差异的布局方向，以及可查看的界面图。此阶段交付图片，尚不修改业务代码。

选择方向后可继续：

```text
采用第二个方向，按这张确认稿实现。
沿用现有技术栈，先说明需要新增的依赖及用途。
把原功能逐项对应到新界面，补齐加载、空结果、失败和中断状态。
给我一个可运行预览；我确认后再完成完整检查与修正。
```

**实施后的交付：** 实际代码、预览入口、功能对应关系、可复用组件说明和实测范围。检查重点是停止操作是否可达、状态是否真实、筛选与记录是否仍能工作。

<a id="case-2"></a>

## 2. 运营数据后台：让关键任务更容易完成

**准备输入：** 现有页面或项目、指标定义、脱敏数据样本，以及用户最常执行的任务。

```text
使用视觉设计工坊改进这个运营后台。
用户主要需要比较不同渠道的转化、按日期和地区筛选，并定位异常。
请先核对现有指标、筛选逻辑和权限状态，研究同类分析产品的任务流程。
给出信息密度和导航方式有差异的方向，不要只更换颜色。
保留指标口径和原始数据，不把示例数据写成真实经营结果。
选定后沿用现有框架实现，先给可操作预览。
```

**预期交付：** 任务与信息层级分析、竞品比较、筛选与图表方案、可操作页面。验收关注单位、日期范围、筛选联动、空数据、错误反馈、键盘操作和窄屏阅读。

<a id="case-3"></a>

## 3. 品牌官网：有表现力的构图与动效

**准备输入：** 品牌资料、目标受众、核心卖点、转化目标、已有文案和素材。新项目还需确认部署环境与技术栈。

```text
使用视觉设计工坊为一家独立咖啡烘焙品牌设计官网。
目标是让访客理解风味与产地，并进入商品选购。
品牌资料、文案和图片已提供，缺少的关键内容请先问我。
研究同类品牌的页面叙事、商品入口和移动端交互，给出 2–3 个方向。
配色和字体根据品牌决定，不沿用固定的科技产品模板。
可以从六个参考网站选择合适组件与动效，但先解释用途和依赖。
选定方向后实现桌面与移动预览，确保动效不妨碍阅读和购买入口。
```

**预期交付：** 带来源的竞品比较、构图与字体方向、页面结构、组件采用说明和响应式预览。检查图片资源、导航、主要转化路径，以及减少动态效果设置下的表现。

<a id="case-4"></a>

## 4. 原生应用：同一品牌，不同平台实现

**准备输入：** 目标平台、现有工程、主要任务流程、已确认的品牌规范；新建工程还需确认最低系统版本和技术栈。

```text
使用视觉设计工坊优化一个同时支持 iOS 和 Android 的习惯记录应用。
核心任务是今日打卡、修改目标和回顾历史，现有工程与页面已提供。
研究同类应用完成这些任务的流程，提出有差异的界面方向。
两端保持一致的品牌和信息层级，同时遵守各自的导航、返回和输入习惯。
参考网站中的配色、构图和动效可以转化使用，不直接套入 Web 控件。
先给关键页面预览，方向确认后实现，并说明各平台可实际验证的范围。
```

**预期交付：** 两端流程与组件映射、设计变量、原生界面实现和可用预览。验收关注返回操作、系统字体缩放、触屏目标、键盘与安全区域；未进行的真机测试单独注明。

<a id="case-5"></a>

## 5. Figma：从现有稿整理组件并交接

**准备输入：** 有访问权限的 Figma 文件或节点链接、目标页面、已有组件库，以及本次允许修改的范围。

```text
使用视觉设计工坊整理这份 Figma 中的注册与登录流程。
先读取指定页面和已有组件，核对字段、错误提示和成功后的去向。
保留已确认的品牌方向，重点改善信息层级、输入反馈和组件一致性。
整理设计变量、Auto Layout、组件变体及加载、禁用、错误等状态。
先给修改预览，再补充面向开发的行为说明与交接规格。
如果当前环境不能直接写入 Figma，请说明实际可交付的部分。
```

**预期交付：** 范围明确的设计修改、组件状态与行为规格、开发交接说明。直接写入和导出只在连接器具备对应能力时执行，不能把文字建议当成已修改文件。

<a id="case-6"></a>

## 6. 报告与演示文稿：让数据支持叙事

**准备输入：** 报告、表格或数据来源、受众、演讲时长、品牌模板和要求的文件格式。

```text
使用视觉设计工坊，将提供的季度经营报告与数据表整理成演示文稿。
受众是管理团队，讲述时间 15 分钟，交付可编辑 PPTX。
先核对指标定义和数据来源，确认最重要的结论与希望推动的决策。
基于现有品牌模板，提供有差异的叙事与版式方向。
图表保持数值、单位、时间范围和来源准确，不编造缺失数据。
先给关键页预览，我确认后完成全稿、渲染检查和修正。
```

**预期交付：** 叙事大纲、关键页预览、可编辑演示文稿和数据来源说明。验收包括图表表达、文本溢出、字体与对齐、备注和导出效果；有指定模板时先沿用模板。

<a id="case-7"></a>

## 7. 海报与社交图片：同一主题适配多尺寸

**准备输入：** 已确认文案、品牌标志、允许使用的图片、投放尺寸和输出格式。

```text
使用视觉设计工坊制作一组书店夜读活动海报。
活动名称、时间、地点和报名方式见附件，先检查是否缺少必要信息。
需要 1080×1440 和 1080×1920 两个尺寸，输出 PNG。
请给出 2–3 个构图与字体层级有差异的方向，并说明素材来源。
选定后分别适配版式，确保小屏能读清时间、地点与报名信息。
需要生成或购买素材时，先说明用途和相关依赖。
```

**预期交付：** 方向预览、选定方案的多尺寸图片和实际素材来源。检查文案准确性、中文字符、裁切、安全边距及标志清晰度；如需可编辑源文件，应在开始时指定。

<a id="case-8"></a>

## 8. 可复用组件：把设计变成项目能力

**准备输入：** 已确认界面、当前代码、组件使用场景和现有设计变量。

```text
使用视觉设计工坊，把确认稿中的任务进度面板做成项目内可复用组件。
沿用当前框架和设计变量，不扩大为跨项目组件库。
状态包括未开始、运行中、暂停、完成、失败与取消，具体状态以业务能力为准。
先说明组件职责、变体、API、状态转换及停止或重试的行为。
实现时保留真实业务回调，动画结束不能当作任务成功。
交付可运行示例、键盘与触屏说明，并检查会影响任务操作的状态变化。
```

**预期交付：** 组件代码、变体 / API 说明、状态映射、设计变量和可运行示例。验证业务状态与显示一致，加载反馈清楚，操作可通过键盘与触屏完成。

## 9. Liquid Glass：修正只有半透明和模糊的工具栏

**准备输入：** 现有组件、实际背景或可共享的背景素材、目标浏览器与设备。补一张网格背景用于检查折射。

```text
使用视觉设计工坊修正这个 Web 工具栏的 Liquid Glass 材质。
保持现有布局和交互，分别实现透、边缘折射、轮廓高光和外阴影。
用 SVG 位移贴图处理背景取样，不扭曲工具栏里的文字和图标。
先关闭背景模糊；如果影响可读性，再给我轻微模糊的对照预览。
圆角跟随现有组件体系，染色按页面底层明暗与色调调整。
用网格背景展示折射开关的差别，并说明目标浏览器的降级表现。
```

**预期交付：** 四层材质的实现与参数、背景线条在玻璃边缘弯曲的可查看预览、目标浏览器的实测或降级记录。验收方法见 [四层玻璃材质](../skills/visual-design/references/liquid-glass.md)。

<a id="case-10"></a>

## 10. 蓝图 + 审查：形成项目自己的设计系统

**准备输入：** 项目、核心任务、目标用户、现有品牌与设计系统。候选需按实际页面用途选择，不能把某品牌的营销页当成后台的完整规范。

```text
使用视觉设计工坊改进这个团队协作工具。
先盘点现有功能和设计变量，研究用户创建任务、筛选和协作的流程。
从 awesome-design-md 中找与当前任务匹配的 2–3 个视觉蓝图，
说明各自适合借鉴的层级、排版、密度和组件规则，等我选定。
将选定蓝图映射到项目 DESIGN.md，保留原始来源与许可。
预览前用 Impeccable 规则检查无依据的紫蓝渐变、毛玻璃和卡片套卡片，
修正实际问题，列出已确认的风格例外，并说明哪些检查真正运行过。
```

**预期交付：** 有依据的候选比较、项目内的原始蓝图参考、适配后的设计约定、实际预览与反模板审查结果。若用户明确指定某种渐变或玻璃，保留该选择并检验用途、可读性与性能。

<a id="case-11"></a>

## 11. 界面细节：清晰层次、柔和文字与果断操作

**准备输入：** 当前页面或组件、实际字体与浅暗主题、流式内容样本、可运行的拖拽与复制操作。

```text
使用视觉设计工坊，按强制界面规范改进这个工作台的细节。
在本次范围内用微明度替代普通 1px 边框，暗色字重数值减 40，
输入框用双环阴影聚焦；核对字体是否真正支持目标字重。
新增流式文字轻微模糊后迅速清晰，数字等宽且跨位数不挤动布局，
行内图标下移 1/8em，展开用自适应网格，正文保护末行排版。
侧边栏拖拽松手立即锁定，不回弹；点赞与复制成功轻微回弹，
复制对勾从本次真实成功起 2.5 秒自动恢复。
给我可操作预览，并检查键盘、减少动态效果、重复操作和卸载清理。
```

**预期交付：** 范围内组件实现、主题与字重映射、可操作预览和实测记录。字体不支持细分字重、换行策略无法保证消除所有孤词等限制需明确说明；不能凭截图声称拖拽或计时行为已通过。

<a id="case-12"></a>

## 12. 交互动效：选择合适效果，而非全页套用

**准备输入：** 现有组件、实际任务、目标设备、已安装动画能力，以及本次允许修改的范围。

```text
使用视觉设计工坊，从八种效果库中优化这几个组件。
产品展示卡片按压时跟随触点 3D 微倾并流转高光，松手阻尼回正；
底部详情抽屉按位移和释放速度选择高度，边界有橡皮筋阻力。
保留侧边栏调整与列表排序松手立即定住的规则。
仅给当前 AI 生成模块加旋转渐变轮廓与弥散背光，记录用途，
其他卡片继续使用微明度分层。操作按钮按下缩放 0.96，释放轻微回弹。
沿用项目已有能力，先说明新增依赖，再给可操作预览。
检查手势取消、快速重复、键盘、减少动态效果和资源清理。
```

**预期交付：** 采用项与组件职责说明、范围内的实际实现、可操作预览及实测记录。完整方案与其他四项效果见 [八种交互动效](../skills/visual-design/references/motion-recipes.md)；不能用静态截图声称跟手、物理吸附或性能已验证。

## 迭代时怎样继续

已选定方向后，直接说明要改的部分及保留的决定，无需重新开启整轮设计。例如：

```text
保留已确认的布局、组件和交互，只把强调色改为天蓝色。
同步检查文字、按钮和状态标签的可读性，先给我更新后的预览。
```

确认预览后可继续：

```text
这个方向确认，继续做完整检查和修正。
按实际交付检查相关页面、交互、不同尺寸与导出文件，
报告实际通过的项目和未验证项，不把方向确认当成技术验收通过。
```

如果缺少品牌、素材、数据或工具能力，先完成不依赖缺口的部分；会改变设计结果的关键决定仍需用户确认。可用 [设计简报模板](../skills/visual-design/assets/templates/design-brief.md) 整理输入，使用 [竞品分析模板](../skills/visual-design/assets/templates/competitive-review.md) 记录研究。
