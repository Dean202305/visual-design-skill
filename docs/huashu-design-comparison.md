# visual-design 与 Huashu Design：对比和落地

核对日期：2026-11-19。比较基线是 visual-design v1.4.0（`313cd85015aa3686fae41e2ab803494afdfd6bdb`），改进版本为 v1.5.0。

结论：**Huashu 的突出优势是把审美探索做成可执行的视觉工作流；我们的相对优势是已有项目的功能保留、多平台语义、组件状态和用户明确指定的交互细节。** 前者值得吸收，不能把后者替换成 HTML 样稿流程。这里是源码、规范和部分样张的分析，尚未以相同任务进行盲评，不能证明谁生成的界面一定更好看。

## 1. 对象和证据

主要对象为作者独立仓库 [alchaincyf/huashu-design](https://github.com/alchaincyf/huashu-design)，固定提交 [`e8d1148a80d5a281d4247cffe320add3df017928`](https://github.com/alchaincyf/huashu-design/tree/e8d1148a80d5a281d4247cffe320add3df017928)，SKILL 元数据为 3.3.0。不是总技能目录里的同名轻量方向顾问，也不是第三方旧许可分叉。

- **直接检查**：SKILL、方向与工作流、上下文/品牌协议、验证/打磨/评审、Web/动画/幻灯片模块、体检/能力/打磨脚本及部分测试，另查 PPTX 导出说明、Liquid Glass 样张源码；查看了 Web、App、PPT 三张风格总览画面。
- **可核对数字**：该提交树有 92 份风格 HTML：Web 20、PPT 20、信息图 20、App 12、东亚 12、小红书 8。简介仍写 84，README 写 92，不应混用。我们的 84 是社区品牌 DESIGN.md 数量，不是 84 套可直接预览的作品，两类资源不能按数量直接比较。
- **执行验证**：运行对方体检时，本机缺少 Python Playwright，脚本提示跳过且退出码为 0；未安装新依赖，没有把这当成对方体检通过。运行了我们新增的标准库单元测试和使用既有 Chrome/Node Playwright 的浏览器集成检查。
- **未验证**：全部 92 样张的渲染、对方全套导出/云能力/全部测试、两套技能同题生成后的视觉盲评、跨 Agent 客户端逐个实测。因此不引用营销耗时或作者评分作为性能、审美的实测结果。

## 2. 哪些优势成立

| 维度 | Huashu 的实际机制 | 我们 v1.4.0 的情况 | 判断与处理 |
| --- | --- | --- | --- |
| 方向探索 | 六个缩略候选选三个真实方向；同内容、方向卡、截图和真实参考 | 已要求 2–3 方向，但允许较轻的呈现方式 | **它的流程更具体。** v1.5.0 要求方向有实际代表画面，同内容比较，记录借鉴规则；保留 2–3 版和既有授权。 |
| 视觉样张 | 多媒介 HTML 样张与六张总览，能看见字体、布局、色彩关系 | 84 份品牌分析主要是文字规范 | **它的样张资源更直接。** 看过的总览确有明显构图差异；我们仍缺同规模的可运行视觉样张库，本次没有声称补齐。 |
| 真素材与上下文 | 官方 logo/产品图/UI 资产、现有代码变量、参考截图先行 | 已有项目/品牌优先和竞品三维研究 | **不是我们缺少研究，而是它的素材落实要求更具体。** 已补实际画面与无效证据识别，避免只引用品牌名。 |
| 看图打磨 | 原尺寸切屏、问题记录、前后对照，有脚本辅助 | 已有预览验收，缺统一的逐屏问题记录 | **值得采用。** 按实际问题迭代，不照搬固定轮数，不改变先预览确认再全面检查。 |
| 作品检查 | 采 DOM、坏图/字号/对比度/控制台，另有外观相似度启发式 | 原有 23 项自动测试主要验证分发和蓝图导入，并不检查作品 | **它对 HTML 作品的工具化更完整。** 新增范围较窄的只读事实工具；没有实现其全部体检或自动美感评分。 |
| 经验复用 | `learn.py` 与本机外观账本，在后续项目提醒重复 | 项目内规范已有，但反馈证据不统一 | **值得借鉴记录链条。** 改为当前项目内保存用户原话/选择/修改，不建立跨项目全局审美禁令。 |
| 输出管线 | HTML、PPTX、PDF、视频有专用脚本和约束 | 公开版主要路由到宿主授权能力；本地完整包另有历史工作流 | **它在 HTML 原型和动画/幻灯片的集成度更高。** 本次不引入第二套导出运行时；原生编辑要求不能被截图导出替代。 |
| 产品落地 | 明确排除生产级 Web App、SEO 和后端系统 | 覆盖已有项目实现、原生平台与组件状态 | **目标不同。** 我们的功能清单、业务状态、键盘/触屏及目标平台验收仍保留；覆盖面更广不代表每项能力都已实测。 |
| 动效与玻璃 | 有视觉样张和动画实现管线 | 四层玻璃、八种用途动效、取消/复位/减少动态效果等细则 | **我们对用户选定效果的行为约束更明确。** 不直接换成对方示例。 |

## 3. 不能直接照搬的部分

1. **随机风格和重复门槛**：秒数轮盘、强制六候选、既定品牌仍重新做三方向，都会增加成本。对本技能按用途选组件和保留已有选择的流程，只采用真实差异与画面证据。
2. **字体和符号启发式**：体检会提示 Inter/system-ui 等标题字体、多个箭头或等宽小字。这不证明设计差；原生 UI、技术工具和已确认的数字规范可能正需要它们。颜色相似或图片骨架相关也不等于功能设计重复。
3. **Liquid Glass 不能用强模糊替代折射**：所查 `app/02-liquid-glass.html` 使用透明渐变、`backdrop-filter: blur(22px) saturate(180%)`、1px 边缘与阴影，没有 SVG 位移贴图。它是视觉风格样张，不满足我们已确认的透明/折射/高光/阴影四层要求。这个观察仅限该文件，不能推断作者所有实现都如此。[样张源码](https://github.com/alchaincyf/huashu-design/blob/e8d1148a80d5a281d4247cffe320add3df017928/assets/style-specimens/app/02-liquid-glass.html)
4. **HTML 和“可编辑”有边界**：其 PPTX 路线存在 DOM/渐变/背景图等约束；文本可编辑不自动等于图表、组件和全部图层均保留原生语义。保留我们按目标格式实际渲染和编辑验收的规则。[PPTX 说明](https://github.com/alchaincyf/huashu-design/blob/e8d1148a80d5a281d4247cffe320add3df017928/references/editable-pptx.md)
5. **跳过不是通过**：本机执行其体检缺依赖返回 0，是可复现的工具边界，不是缺陷已检查。新工具缺文件/证据错误返回 2；即便没有发现坏图，也输出 `needs_review`。[采集与退出逻辑](https://github.com/alchaincyf/huashu-design/blob/e8d1148a80d5a281d4247cffe320add3df017928/scripts/design_lint.py)
6. **许可须分项保留**：上游主体为 MIT，演示贴纸有另行条款，不能全目录当 MIT 复制。我们原创内容目前仍未指定统一开源许可证，这是公开复用的一个实际短板；本次不擅自替所有原创内容授予 MIT，第三方许可照常保留。[上游许可说明](https://github.com/alchaincyf/huashu-design/blob/e8d1148a80d5a281d4247cffe320add3df017928/README.md#license)

## 4. 已落地到 v1.5.0

- [设计证据规范](../skills/visual-design/references/design-evidence.md)：真实参考 → 可见初稿 → 用户选择 → 看图修正 → 受影响范围复查；同步接入主入口、竞品、实施和验收流程。
- [项目记录模板](../skills/visual-design/assets/templates/design-evidence.md)：复用项目已有目录，记录必要的用户原话和证据，不写全局账本，不覆盖已确认偏好。
- [作品事实工具](../skills/visual-design/scripts/design_audit.py)：浏览器只读采集普通 DOM 文字计算样式、图片状态、视口/横向溢出，Python 标准库分析。无需新增 Playwright/Pillow 或云依赖；使用宿主已有浏览器求值能力，不能自动替用户安装运行时。
- [来源与适配](../skills/visual-design/resources/design-core/huashu-design/ADAPTATION.md)：固定提交和许可校验，只保留 MIT 许可；不捆绑对方原版脚本、样张、演示贴纸、云工具或 hooks。
- [案例 13](examples.md#case-13)：给出可复制的真实方向对照与检查请求。

事实工具故意不自动估算复杂背景上的对比度，不按色彩/字体判美感，不检查全平台状态。相比对方完整 HTML 管线，自动化范围更窄、采集需要宿主浏览器配合；这是避免额外依赖与错误“通过”的取舍。

## 5. 实际验证及剩余工作

- 原有 23 项测试加 8 项事实分析测试，共 **31 项通过**：覆盖分发/安装/蓝图完整性、新证据格式、坏图与加载中区别、错误退出、项目阈值、未知范围及输入不变性。
- 既有 Chrome + Node Playwright 集成检查覆盖 **1440×900、390×844**：实际 DOM 采集 → JSON → CLI，坏图返回 1，横向溢出进入复核，表单/可编辑内容与被祖先隐藏的文字不进入正文采样，开放 Shadow DOM 计数但不声称已覆盖内部。
- Python Playwright 未安装；首次默认 Chromium 启动发现缺少其缓存浏览器，随后使用本机已有 Chrome 完成检查，没有下载浏览器。以上是采集器行为验证，不是生产项目或所有客户端验证。
- 本次未做同题视觉盲评；“提升美观度”的结果仍需真实项目预览和用户判断。后续最有价值的是用一套真实内容做同题方向实验，并逐步沉淀经认可的可运行样张，而非继续增加风格禁词或素材数量。

升级前已另行完成 v1.4.0 的本地完整快照与公开两种安装包；本地完整包保留历史受限资源，不能作为公开发行包。视频切片研究随本地研究快照保留，未声称其全部结论已写入本次技能。
