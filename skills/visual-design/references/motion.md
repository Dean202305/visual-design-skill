# 动效与视觉表现

用户偏好优先视觉表现，接受较多 3D、粒子和滚动叙事，同时要求操作流畅。按场景决定表现方式；不默认轻动效、不固定每页效果数量，也不因为操作使用键盘就一律取消所有视觉反馈。

## 先决定看到什么

说明效果的目的、承载内容、触发和结束状态。区分交互反馈、状态连续性、内容解释、品牌表达与环境氛围。工具界面保持任务可操作，品牌页面可以用复杂编排，但主要内容不能依赖动画完全播放后才能访问。

为每个效果定义：触发方式、被影响对象、开始/结束状态、时间编排或物理行为、快速反复操作、离开页面、低性能与减少动态效果下的表现。连续运动要有适当的暂停/静止方式，尤其当它与长时间阅读共存时。

## 再选择实现

| 已确定的需求 | 实现方向 | 关键核对 |
| --- | --- | --- |
| 简单状态反馈、hover/focus/pressed | 现有框架能力或 CSS/原生动画 | 无需为几个属性强加引擎；只过渡实际需要的属性 |
| React 组件的布局、进入退出、手势弹性 | 项目已有方案；合适时采用 Motion 等 | 当前版本 API、退出生命周期、快速中断与布局 |
| 时序、SVG、文字、交错、路径动画 | Anime.js 或项目已有引擎 | 按当前文档核对 API、作用域、卸载与静止终态 |
| 复杂时间线、滚动联动、跨对象编排 | GSAP 或已验证方案 | 滚动容器、响应式重算、作用域、清理与阅读节奏 |
| 真实 3D、材质、场景、粒子/着色器 | CSS 3D、Canvas、WebGL/Three.js 等按效果选择 | 真实渲染需要、资源体量、分辨率、GPU/主线程开销 |
| React Native/Expo 手势与动效 | 平台已有方案、Reanimated/手势系统等 | JS/UI 运行时、交接速度、导航生命周期、真机 |
| 原生应用 | 平台动画、转场和手势机制 | 控件行为、可中断性、平台可访问性与减少动态效果 |

这是需求映射，不是固定依赖清单。优先兼容现有栈；参考组件要求新依赖时说明后采用。不要在同一属性上让多个引擎争夺控制。

## 细节标准

- 按操作频率、位移、内容和媒介设定时长与缓动；进入反馈通常尽快出现，手势释放要连续。短暂控件、整页叙事与长镜头不共用一个时长上限。
- 锚定组件从触发位置建立空间关系。中断或反转从当前显示状态继续，不能跳回预设起点；快速操作不排长动画队列，也不锁住输入等待结束。
- 根据效果选属性。优先采用对目标设备友好的实现，但不把“只许 transform/opacity”推广为 SVG、Canvas、3D 和必要布局变化的禁令。测量布局、绘制、合成与脚本开销；不要承诺某个库属性必定由 GPU 执行。
- 对渐变、模糊、滤镜、粒子和高分辨率画布检查面积、刷新成本与叠加影响。按需要延迟加载、降低分辨率/数量、暂停离屏与后台循环，及时释放监听、帧循环、纹理和观察器。
- `prefers-reduced-motion` 或平台相应设置下提供可读、可操作的静态/温和版本，不让内容停留在透明或画外。触摸平台为悬停专属效果提供等价路径。
- 动态文字保留可读取内容与合理阅读顺序，避免逐字变化不断触发辅助技术播报。数据动画不能伪造数值、完成状态或因果关系。

## 预览与检查

方向预览让用户看到真实速度和主要交互，不只给动效截图。确认方向后，检查连续操作、反向操作、滚动恢复、窗口变化、内容变化、减少动态效果与后台恢复。涉及物理手势和性能判断时使用相应设备或性能工具；无法实测就明确限制，不能仅凭代码声称流畅。
