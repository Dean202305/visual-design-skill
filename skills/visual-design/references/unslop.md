# 已有界面的诊断与精修

适用于“这个界面很 AI”“按设计师的方式改稿”“精修这个页面”。从实际屏幕开始。Impeccable 辅助找问题，awesome-design-md 提供候选蓝图，unslop 组织改动顺序。已有品牌、用户选定的材质、产品能力与平台交互约定继续生效。[原作与改编说明](../resources/design-core/unslop/ADAPTATION.md)

## 先看用户在哪一步受影响

打开目标入口，等待字体、图片和关键业务数据就绪。留一张基线图，记下视口、主题、页面状态和主任务。有源码时找到真实入口；只有链接就对照可访问的实际页面做本地提案；只有截图就标注可见范围，交互行为列为待验证。需要对外分享时，从第一张图起使用可分享的数据。

逐项写「位置 → 可见现象 → 对任务的影响 → 拟改动作」。例如，审批列表每一行都有高饱和底色，待处理与已完成的区别只剩小字；把颜色留给逾期状态，其他行用文字和明度区分。渐变、玻璃或留白都需要结合用途判断。业务警示色、数据系列、品牌标志分别核对。

| 诊断 | 接下来做什么 |
| --- | --- |
| 多层问题互相影响，或明确要求完整重做 | 列出覆盖范围、功能和状态清单。按下表依次审视全屏，把命中项落实到代码或设计源文件。 |
| 少量孤立问题 | 沿用现有方向，只执行相关轮次。例如两个列表数字跳动，修正数字样式并验证刷新前后的列宽。 |
| 当前设计已支撑任务 | 说明观察依据，至多列出两三项有明确收益的可选微调，等用户决定。仅要求评审时交付诊断即可。 |

方向落在五个具体判断上：谁在这里完成什么任务；页面要传达的气质；颜色、材质或排版从哪个业务场景取材；注意力应该落在哪一两处内容；哪个细节让用户认得出这个产品。文字密集的后台可以让下一条待处理事项成为焦点。方向未定时按既有流程给 2–3 个真实方案，已选方向直接沿用。

## 九轮精修

每轮先横向查看同类组件，再调整共享变量或组件。已满足的项记为「保留」并说明依据。先把当前屏做对，再扩到确实复用该组件的入口。

| 顺序 | 实施与观察 |
| --- | --- |
| 1 间距 | 比较相邻行、同级卡片与分组的实际距离。消除破坏分组的孤立值，保留触控热区和光学对齐。 |
| 2 配色 | 分清表面、动作、业务语义和数据系列。用微明度组织表面；在选中、禁用和深色主题下核对文字辨识度。 |
| 3 图标 | 同类操作使用同一家族、笔画和视觉尺寸；对齐字与图标的光学中心。图标按钮校验可访问名称。 |
| 4 文案 | 用业务对象和动作写标题、按钮和反馈。保留字段含义、操作后果、真实数据及必要提示，删掉遮挡主任务的套话。 |
| 5 字体 | 用真实长标题、中文与数字核对字号、字重、字距、断行和等宽数字；沿用平台与用户批准的字体。 |
| 6 布局 | 按用户阅读和操作顺序处理对齐、密度、窄屏。重排业务步骤、删减功能或改变导航含义属于范围变化。 |
| 7 细节 | 检查内外圆角、输入聚焦、可点击区域、键盘顺序、空态与错误态。用真实路径确认动作仍可达。 |
| 8 视觉素材 | 选择有助于理解任务的产品截图、图表或材质；文字工作台可保留纯文字。重看产品识别度和主体留白。 |
| 9 动效 | 为反馈、状态变化或空间连续性设置动效；验证可打断、焦点归还、减少动态效果与低性能情形。按组件使用已批准的反馈与材质。 |

若把产品名换掉，画面仍像另一个产品，先检查主任务、文案与所选视觉素材。无需为制造区别强加装饰。用同视口、同数据、同状态复拍，逐项记录「改动／保留／待验证」。先给预览；用户确认后再走 [完整验收](review.md)。样式检查不能替代关键业务路径验证。

## 按需制作改稿视频

只有用户明确要视频或准备分享时才制作。本地导出与对外发布分别处理。如开工前已确定要视频，在修改前留基线，在有可见差异的节点保存真实状态。中途才提出时，可用历史版本还原；只有前后两张图时只展示能佐证的两态，不补造九个过程画面。

1. 选同一屏的 3–5 个可见变化，或仅用已有的前后两态。在项目单独的演示目录写 story.html，放入获准使用的本地素材、字体。基线来自原画面，最后一态对照已确认的预览，演示中使用的示例数据应标明。原生端也可用同尺寸实拍截图展示实际状态。
2. 下面的 meta 放入 head。原始结构表现起点，在样式表通过 html.s1、html.s2 等累加规则表现每次实际改动。示例中的数字与控件名需换成项目实测值。使用 data-gap 标记同组的相邻块，data-radius 标记需要展示的控件，data-slop 标记具体诊断；只标本次要解释的变化。用中文“间距”“细节”或英文 Spacing、Details 可触发对应红线。镜头的三个数表示原页面坐标 x、y 和取景宽度。

   ```html
   <meta name="unslop-steps" content="间距,文字层级,细节">
   <meta name="unslop-frame" content="0 0 960">
   <style>
     .queue { padding: 12px; border-radius: 24px; }
     html.s1 .queue { padding: 24px; }
     html.s2 .queue h2 { font-size: 22px; }
     html.s3 .queue { border-radius: 12px; }
   </style>
   ```

3. 将 SKILL_DIR 设为当前宿主中 visual-design 的安装目录。从可解析 Playwright 或 playwright-core 的项目目录运行。需要 Node.js、Chromium/Chrome 和带 libx264 的 FFmpeg；已有安装可用环境变量 CHROME_PATH、FFMPEG_PATH 指定。Playwright 安装在独立工具目录时，可将该目录的 node_modules 赋给 NODE_PATH。缺依赖时先说明所缺项，再按项目依赖约定处理。默认正方形，可加 `--wide` 输出 16:9。输出使用新文件名。

   ```sh
   node "$SKILL_DIR/resources/design-core/unslop/story.mjs" ./story/story.html ./iteration.mp4
   ```

4. 用播放器或媒体探针确认 MP4 可解码、时长不超过 10 秒，查看首、中、尾帧，确认文字与署名可读，视频中没有客户资料或测试凭据。保留作者署名并交付本地路径。渲染失败时区分已完成的页面改稿、演示源文件与未完成的视频。
