# 预览、检查与交付

用户约定的顺序：基本可运行检查 → 可预览版本供用户确认 → 完整检查与修正 → 交付。提供方向探索样例与提供完整作品预览的目的不同，说明当前阶段。

## 预览前

- 验证入口和主要资源可用、核心内容可见、展示出来的主要交互能工作。
- 给出实际查看位置和本轮需要确认的问题；若展示了模拟内容或不可用能力，明确标注。
- 设计决策仍待用户回答时保持待定，不把沉默算为选择，不提前接入其中一个方向。

## 用户确认后

| 产物 | 实际检查 |
| --- | --- |
| Web / 跨平台界面 | 项目相关编译/类型检查，关键任务与适用状态，键盘/触屏，焦点，布局与内容极值，约定尺寸，主题，减少动态效果，资源和控制台错误 |
| 原生应用 | 对应平台构建或预览，原生导航/返回/窗口行为，可访问性与文本缩放，真实设备上的关键手势与运行表现 |
| Figma | 节点与层级，组件/变量绑定，布局适配，文字溢出、实际截图及与目标设计的对照 |
| 图片 / 视频 | 主体与裁切，文字准确性，比例/分辨率/透明度，编辑要求，动画时间线/接缝/最终输出，实际预览 |
| Word / PDF | 按格式实际渲染页面，检查分页、表格、字体、图像、溢出及阅读顺序；需要的表单字段等原生能力仍可使用 |
| 幻灯片 | 逐页预览，字体与元素适配，阅读层级，图表/表格/图示的原生编辑要求与模板一致性 |
| 表格 / 图表 | 计算及数据来源，单位、尺度与比较语义，图表标签、颜色与非颜色编码，显示范围和导出结果 |

按实际任务选择检查项，不要求静态图片提供键盘交互，也不以静态截图代替控件行为验证。自动工具只能证明其检查到的内容；相关用户路径仍应实际操作或明确未验证。

可访问性依据目标平台和当前适用规范核对：语义与标签、可见焦点与顺序、可读对比度、可缩放文字、适当命中区域、非颜色信息表达和替代操作。不要把一个平台的 px 数值当作所有平台统一合规标准。

修正实际问题后，对受影响路径复查。没有新改动、失败或未解决风险时不重复扩大测试。用户提出新的视觉方向时回到方向确认，技术缺陷修正则沿用已选定设计。

## 完成说明

提供代码/文件、预览入口、必要复用说明，以及实际做过的检查。将“用户已认可设计”“技术已验证”“尚待设备/连接器验证”分别写清。缺少目标运行环境时保留可审阅源码和正确启动/验证步骤，不用另一个媒介冒充最终完成。
