# Liquid Glass：四层材质与可选模糊

当任务明确要求 Liquid Glass，或选定玻璃材质后需要做出透镜效果时，按四个独立职责实现。四层是视觉职责，可以合并绘制；不要求四个 DOM 节点。普通半透明或磨砂表面按其实际效果命名。

| 层 | 作用 | Web 实现与判断 |
| --- | --- | --- |
| **透** | 让后方内容透过材质可见 | 只降低玻璃底色的 alpha，保留文字、图标、控件和焦点环本身的清晰度。不要在整个容器上降低 `opacity`。 |
| **折射** | 让背景轮廓穿过玻璃边缘时弯曲 | 用 SVG `feDisplacementMap` 和位移贴图改变**背景**取样坐标。中心保持近乎原位，靠近边缘和圆角时沿轮廓产生连续偏移。 |
| **高光** | 勾勒玻璃轮廓，表现厚度和光向 | 用贴合轮廓的 CSS 渐变描边或内阴影。受光侧更亮，避免用满铺亮色盖住背景细节。 |
| **阴影** | 拉开玻璃与背景的距离 | 用外层 CSS `box-shadow` 表示悬浮高度，按页面明暗和组件层级调节；避免被材质层裁掉。 |

**可选：背景模糊。** 从关闭开始，在背景太杂、影响前景阅读时尝试轻微模糊。只处理玻璃内的背景采样，不处理前景、高光或外阴影；比较开启和关闭两种状态，确保仍看得到边缘折射。模糊不能替代折射，也不是四层基础的一部分。

## Web：先确定滤镜处理的是哪一张图

`feDisplacementMap` 使用第二输入的通道值偏移第一输入的采样坐标。例如分别用 R/G 编码 X/Y 方向，通道值在运算色彩空间中以 `0.5` 为零偏移。位移图要与玻璃的尺寸、圆角和坐标对齐；中心接近中性，边缘采用与轮廓对应的平滑位移。检查采样范围与裁剪，避免边缘出现空像素、断裂或错位。它是背景像素的重采样，用于近似视觉折射。

- **实时页面背景**：只有在目标浏览器实测有效时才使用 `backdrop-filter: url(#glass-refraction)`，让 SVG 滤镜处理玻璃后方的图像。`CSS.supports()` 为真或计算样式保留了 URL，都不能证明滤镜实际渲染。遇到看不见效果时，也检查祖先滤镜、透明度或其他会改变 Backdrop Root 的属性。若同用模糊，将它与位移纳入同一滤镜链，避免两条 `backdrop-filter` 声明相互覆盖。
- **受控背景素材**：若背景是可共享的图片、SVG 或项目自行绘制的画面，可复用同一背景源，按位置、缩放、滚动对齐后在玻璃区域内做位移和裁剪。只给背景副本加 `filter: url(...)`；给面板本身加 `filter` 会影响面板自己的像素，不能以此采样任意背后的 DOM。
- **无法取样或性能不达标**：保留透、轮廓高光、外阴影，按可读性决定是否轻微模糊或加强底色。将效果标为玻璃降级版；若项目要求完整折射，说明缺失的浏览器或场景，并比较受控背景或其他已验证的实现。

## 圆角、底色与前景

- **用同一轮廓**：材质裁剪、折射范围、高光和外阴影共享容器圆角。内缩描边按内缩距离推导内半径；同类组件统一半径变量，尺寸不同的嵌套层保持同心关系，避免露角或双边。
- **底色随页面**：按页面底层的色调、亮度和内容复杂度选择低透明度染色，可按主题或已知场景设变量。浅底、深底、图片底分别检查；前景对比不足时，优先调整局部底色或前景色，避免靠强模糊抹掉边缘细节。
- **前景单独合成**：外层负责投影，裁剪仅用于材质，高光盖在材质上，文字与控件保持独立。装饰层不截获点击或遮住焦点；浮层、键盘和触屏行为沿用组件约定。

## 预览与验收

1. 在有直线、网格或明确轮廓的背景上，关掉模糊，对比折射开关：背景线条在边缘附近弯曲，中央基本稳定，前景文字不变形。纯色背景不足以验证位移。
2. 在实际浅色、深色和图片背景上核对透感、对比度、高光、阴影和圆角；对比模糊开关，确认增加柔和度后边缘细节仍可辨认。
3. 检查目标浏览器和设备的滚动、缩放、布局变化及主要操作，核对采样位置、掉帧和降级效果。记录哪些环境实际渲染出折射，哪些仅验证了降级；视觉稿不作为浏览器兼容的证据。

技术依据：[W3C SVG 位移原语](https://www.w3.org/TR/filter-effects-1/#feDisplacementMapElement)、[CSSWG 背景滤镜与裁剪](https://drafts.csswg.org/filter-effects-2/)、[WebKit SVG 背景滤镜兼容问题](https://bugs.webkit.org/show_bug.cgi?id=245510)。
