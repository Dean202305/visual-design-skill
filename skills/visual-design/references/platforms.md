# 平台适配

平台策略：共享质量、品牌和概念，保留原生控件语义与平台习惯。每个项目读取实际工程与目标版本，不能预设技术栈。API、规范和浏览器能力在使用时核对当前官方来源。

| 平台 | 实现与验证重点 |
| --- | --- |
| Web | 语义 HTML、链接与按钮角色、表单、焦点、键盘、响应式内容布局；适配现有框架与组件库 |
| 移动 Web / H5 | 触摸与悬停的差异、安全区、软键盘、滚动容器、视口变化、文本缩放、手势冲突；按产物判断是否需要独立手机版 |
| React Native / Expo | 原生组件与可访问性属性，导航、列表、手势系统，运行时与卸载清理；不直接粘贴 CSS/DOM/WebGL 组件作为原生组件 |
| Apple 原生 | 根据 SwiftUI/UIKit/AppKit 等现有工程实施，保持平台导航、返回、菜单、窗口与控件行为；检查文字缩放和系统减少动态效果 |
| Android 原生 | 根据 Compose/Views 工程实施，保留系统返回、导航、窗口/折叠屏适配、输入与语义；按用途选择 Material 或项目已有设计系统 |
| Windows / 桌面 | 根据现有 WinUI、WPF、跨平台或 Web 容器实施，保留窗口、键盘、焦点、菜单和平台约定；区分控件内容与自定义窗口装饰 |

先提取参考的用途、层级、配色、构图、状态反馈与动效轨迹，再映射到目标平台能力。保留品牌表达不等于复制 Web 控件外壳；原生交互语义也不要求放弃用户选定的视觉表现。

同一功能跨平台时，用相同业务状态与设计变量角色组织，明确每个平台的控件、单位、字体回退和行为差异。不要将 CSS px、iOS pt 和 Android dp 混作一个固定数值。

## 适配检查

- 布局由实际可用空间和内容决定；预览设备框不写死为生产视口。表格、编辑器、导航和主要操作按使用方式重新组织。
- 长标题、中英混排、缩放文字、空状态与大量内容不会破坏层级。允许复制的正文保持可选取；不要全局禁用缩放或文本选择。
- 手势与滚动同时存在时检查取消、指针捕获、边界和替代操作。鼠标专属展示为触摸用户提供等价查看方式。
- 移动 Web 中按容器选择 `svh`/`dvh` 等单位；固定操作区与安全区不能遮住内容，输入时软键盘不能盖住必要操作。
- 真实运行检查与浏览器设备模拟分别记录。缺少平台 SDK/构建环境或真机时，不声称原生构建或手势验收已通过。

平台实现按 [技术入口](resources.md) 读取官方文档，并优先使用现有项目和当前可用的 Swift、WinUI、Android 等工程能力。

官方起点：[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/)、[Android Design](https://developer.android.com/design)、[Windows controls](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/)。具体项目按控件和目标版本继续检索。
