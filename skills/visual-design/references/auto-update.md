# 自动更新

从 v1.8.1 起，每次调用都先请求 GitHub 最新正式 Release，检查和可能的升级结束后再开始设计。检查需要 Python 3.9+ 和 GitHub 网络访问。升级官方安装包或安装器创建的标准副本还需要写入技能目录和相邻更新目录的权限。检查失败或执行受限时，接着使用已安装版本。

更新器按已装版本识别 Portable 或 WorkBuddy 包，使用 GitHub 提供的 SHA-256 校验下载，并在替换前验证新包及当前文件。成功时输出 `updated`、新版号和旧版备份路径。需要恢复时，在技能未使用时移出新版，把备份移回原目录，再开启新会话。

在技能目录之外运行，路径指向已安装的技能：

```bash
python3 "/技能目录/scripts/update.py" --check
python3 "/技能目录/scripts/update.py" --now
```

`--check` 只比较版本。`--now` 可以立即检查和升级符合条件的安装，也可用于旧版接入。普通调用遇到断网、只读目录、被 Git 跟踪的安装，或本机改动时，继续当前任务。用户主动询问更新结果时按脚本状态报告。把环境变量 `VISUAL_DESIGN_AUTO_UPDATE` 设为 `0` 可暂停自动检查，手动命令仍可用。

旧版通过 v1.8.0 或更新版本中的脚本运行 `--now --skill-dir <已安装的目录>` 接入。更新器会先与旧版 GitHub 发布包核对。WorkBuddy ZIP 也可通过客户端重新导入一次接入，自动更新取决于客户端是否给当前会话提供原始可写目录和运行权限。

自定义副本的文件由原维护者管理，Git 跟踪的目录随所属仓库更新。设计记忆和 PPT 模板索引继续由 [设计记忆](design-memory.md) 在本机管理。
