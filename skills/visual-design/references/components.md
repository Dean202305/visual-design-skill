# 按用途选择和交付组件

先判断用户动作、内容和反馈需求，再从来源中找组件，最后适配外观。名称、动效或缩略图相似，不足以证明用途匹配。视觉参考与可直接使用的实现要分别核实。

各界面组件适配 [强制细节](interface-craft.md)：输入框双环阴影聚焦、变化数字等宽、行内图标偏移、网格展开、即时拖拽终态与复制反馈自动恢复。相关状态、计时清理和键盘行为纳入组件契约，不能只复制视觉外壳。

## 语义选择表

| 用户需要 | 优先考虑 | 需要避免 |
| --- | --- | --- |
| 执行操作 / 跳转位置 | 操作按钮 / 导航链接 | 只有外观而没有正确角色、键盘行为或目标 |
| 独立多选 / 互斥单选 / 即时设置开关 | Checkbox / Radio、单选组 / Switch | 用开关表示需要统一提交的互斥选项而不说明 |
| 切换同层内容 / 完成有次序的任务 | Tabs / Stepper、向导 | 用页签隐藏必须按顺序验证的步骤 |
| 在上下文中选择操作或查看信息 | Menu、Popover | 无焦点管理的悬浮 div；把必需信息只放在 hover 中 |
| 必须处理的临时任务 / 连续查看详情 | Dialog / Drawer、详情面板 | 任意弹窗打断无关操作，或长任务只能靠短暂弹窗承载 |
| 可选提示 / 非阻塞结果 / 需要修复的错误 | Tooltip / Toast、状态区域 / 就地错误与恢复操作 | 仅用转瞬即逝 toast 告知必须修复的表单错误 |
| 比较同类对象的多个属性 / 浏览异构内容 | Table、List / Card、Gallery | 为追求卡片视觉破坏横向比较能力 |
| 等待未知结果 / 可计量任务进度 | 不确定进度 / 确定进度与步骤记录 | 虚假百分比或未成功就播放成功反馈 |
| 输入和编辑内容 | 具有可见标签的输入控件与适当编辑器 | 仅 placeholder 作为标签；特效清除尚未提交内容 |
| 拖动调整或排序 | 对应拖动组件及可替代操作 | 拖动成为唯一途径，触摸与键盘无法完成同一任务 |

## 来源组件的采用流程

1. 明确用途、内容量、预期状态和目标平台。
2. 从 [来源索引](sources.md) 找对应类别，查看具体组件页面、实现与依赖，记录链接。核实免费/付费边界和具体许可；网站整体定位不代表每个资源许可相同。
3. 选择符合用户方向的候选，并说明其适用理由；不要为使用参考组件而重构无关业务或迁移现有框架。
4. 新增依赖先说明用途后采用；已有授权继续有效。把外部组件通过项目自身组件接口与设计变量适配，不让来源的固定颜色、字体和页面文案散落在业务代码中。
5. 将示例回调和假数据接入真实任务。增加适用的失败、重试、加载与中断行为。不能把示例动画播放完毕当作业务操作成功。
6. 检查焦点、键盘/触屏、内容溢出和运行表现。对仅供视觉展示的实现补齐语义与行为，或换成语义合适的底层实现并保留选定外观。

## 项目内复用约定

为本次需要重复使用或维护的组件，明确以下内容，沿用项目现有位置和文档格式：

- 用途、适用/不适用场景、来源及适用平台。
- 设计变量与尺寸/外观/意图变体；外部业务数据通过参数或插槽传入。
- 属性/API、受控/非受控边界、事件、异步结果和禁用语义。
- **适用状态**：default、hover、focus-visible、pressed、selected、disabled、loading、empty、error、success 等按用途选择，不强制每个组件全部具备。
- 键盘、焦点、触屏与屏幕阅读行为；纯装饰和交互元素明确区分。
- 动效触发、中断、减少动态效果行为及资源清理。
- 可运行的使用示例与适用状态预览，包含真实长文本、空内容和错误情况中的相关案例。

不要把一次项目内复用擅自扩展为跨项目资产库或发布包。纯展示图片、图表和排版区块不应为满足统一清单而添加虚假的按钮状态。
