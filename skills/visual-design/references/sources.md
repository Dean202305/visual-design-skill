# 六个参考来源与采用规则

本索引用于寻找合适的实现与表现手法；正式采用时核对具体页面、版本、实现、性能、可访问性和许可，不把列入索引当作逐组件验收通过。

| 来源 | 主要用途 | 采用方式与判断 |
| --- | --- | --- |
| [Aceternity UI](https://ui.aceternity.com/components) | React 页面区块、卡片、导航、表单、文本和背景效果 | 按控件用途选具体实现，适配项目变量与 API；检查语义、状态、内容量及 Motion/Tailwind 等依赖。免费与 Pro 内容分别核对。 |
| [Swishy](https://www.swishy.ai/) | 文字、图形、产品演示与 UI 动画的表达参考 | 研究主体、镜头、节奏和状态变化；需要生成/导出时检查工具与资源可用性。模板截图不能视为交互控件源码。 |
| [Anime.js](https://animejs.com/documentation) | 时间线、SVG、文字、路径、交错和滚动编排 | 在动效目的明确后采用；按当前版本核对 API、scope、响应式、清理与静止终态。它是引擎，不是完整 UI 组件库。 |
| [MotionSites](https://motionsites.ai/) | 页面构图、区块节奏、3D 与动态背景参考 | 将符合用途的构图与表现转为设计方向；具体提示词、模板、素材的使用条件分别核对，不假定都有可移植源码。 |
| [React Bits](https://reactbits.dev/get-started/introduction) | 文字动画、表现组件、背景和微交互 | 选择适合项目的语言/样式变体，核对依赖和浏览器行为；局部表现与产品系统协作，不默认取代全部基础控件。 |
| [Uiverse](https://uiverse.io/elements) | CSS/Tailwind 按钮、输入、开关、卡片与加载元素 | 采用具体控件表现；样例需补齐业务、语义和适用状态，验证键盘、焦点、触屏及内容变化，记录作者/来源和许可。 |

## 按需求组合

- 异步操作按钮：先定义提交、等待、失败/重试、成功等实际需要的状态，再考察 [Aceternity Stateful Button](https://ui.aceternity.com/components/stateful-button) 等候选。示例动画不等于业务结果，必须连接实际返回值。
- 品牌首屏：从 MotionSites/Aceternity 中选择构图，从 React Bits/Swishy 中研究局部表达；需要编排时再按目的选择 Anime.js、现有引擎或原生能力。
- 输入/开关：从 Uiverse/Aceternity 中找视觉候选，功能语义、焦点、错误说明和反馈按用途落实。
- 原生应用：提取视觉与运动关系，用平台控件和动画机制实现；Web 源码不直接复用为 SwiftUI、Compose 或 WinUI 控件。

这些是查找起点，不要求每次同时使用六站，也不限制只能采用它们。项目既有组件、用户设计稿和适当平台控件仍可优先满足用途。

同类产品研究按 [竞品分析](competitive-analysis.md) 执行：从需求出发搜索真实产品，研究对应界面与任务流程；本页六站用于寻找实现与表现手法。竞品结论先帮助确定方向，再用本页来源寻找合适的组件和动效。

记录每个采用资源的用途、具体链接、作者/许可（可获取时）、版本/取得日期、平台、依赖、适配点与验证范围。只保存本次需要的记录，不批量复制整个目录。未核实的许可、性能和可访问性不能写成已验证。
