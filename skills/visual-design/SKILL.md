# 视觉设计工坊

为实际用途设计，统一质量标准，保留不同产品、媒介与平台的表达空间。规范用中文，代码、库名和 API 保持原名。本包包含独立的工作规范与可复用模板；实际执行使用当前项目、已安装工具和官方 API。

## 宿主适配

本技能采用通用 Agent Skills 结构，设计流程不绑定特定模型、工具名、系统路径或付费服务。开始任务时先读 [Agent 能力适配](references/agent-runtime.md)，确认当前宿主能读取的文件与可用工具；引用一律相对本技能目录解析。

支持按任务自动选择的宿主可按描述触发；显式调用语法由宿主决定，无法自动发现时可直接要求读取本文件。`agents/openai.yaml` 仅是 Codex 的可选界面元数据，其他宿主无需读取。

## 工作约定

- 先确认用途与限制，再提供 **2–3 个有差异的设计方向**；等待用户选择后实施，重大变化再确认。利用已有对话与项目决定，不重复询问，不替用户猜测关键偏好。
- 理解用途时，依据用户需求搜索同类产品，研究其设计、交互逻辑和界面样式，形成有来源的比较与取舍，再用于设计方向；具体范围与证据要求见 [竞品分析](references/competitive-analysis.md)。
- 按用途决定风格：后台清晰高效，品牌页更有表现力。**优先视觉表现**，允许较多 3D、粒子与滚动叙事，同时保持操作流畅。
- 不预设字体、颜色、渐变、玻璃、发光或圆角禁令；避免无目的装饰与重复套模板。
- 先按用途选组件，再采用和适配参考来源中的合适组件。现有项目沿用技术栈；新项目推荐后确认；新增依赖先说明用途再采用。
- 原生应用保留原生控件语义与平台习惯，将参考来源的配色、构图和动效转为平台实现。Web/CSS 组件不视为能直接运行于原生 UI。
- 交付项目内可复用组件规范：设计变量、变体/API、适用状态、键盘/触屏行为及可运行示例；不默认维护跨项目资产库。
- **先给可预览版本让用户确认，再做完整检查与修正。** 预览前仍检查基本可运行性；用户确认设计方向与完整验收通过分别记录。

## 执行流程

1. 读取 [工作流程](references/workflow.md)。盘点实际输入、品牌、技术栈、模板与工具能力，明确用途后按 [竞品分析](references/competitive-analysis.md) 搜索同类产品及相关任务流程。对会改变结果的未知项分批提问，继续推进不依赖答案的研究。
2. 结合竞品发现与 [质量标准](references/quality.md) 提出符合用户需求的设计方向，说明借鉴点、取舍和差异。新建/重设计且方向未定时展示差异；已指定方向的局部修复延续已有决定。
3. 涉及界面时读取 [组件规范](references/components.md)；有动态表现时读取 [动效规范](references/motion.md)。根据用途、平台、内容和状态决定组件，再选来源与实现。
4. 读取下表中的相关模块，实施并提供实际预览。**只加载本次任务需要的技术参考**，不要一次性阅读全部历史材料。
5. 用户确认预览后按 [验收规范](references/review.md) 检查并修正，交付实际代码/文件、复用说明、查看入口与已验证范围。

## 技术与工具边界

本包的 references 是完整设计工作流，assets/templates 是可复制到项目的工作底稿。按需读取，不批量加载。第三方组件、字体、模板、插件与运行时不随包分发，采用前检查当前官方文档、具体许可和现有项目依赖。

文件、Figma、图像或视频任务需要对应工具实际可用。先核对当前工具 schema 与前置条件；缺少连接器或运行环境时，完成可审阅部分，明确不能执行的步骤，不声称已写入、渲染或发布。

若环境中有专门处理对应格式或平台的技能，按其当前运行约束执行，不将其私有说明复制进项目。用户已确认的方向和授权持续有效；不因本规范重复索要同一授权。

只读评审、解释或局部修复按实际范围完成，不扩展成整页重做、替换技术栈或外部发布。
